inline JavaScript

Similar to #ilASM{ ... } for inline assembly, Phix also uses #ilJS{ ... #}ilJS for embedded JavaScript code.
Most applications should not need this at all, in fact there were over 1,250 fully working programs that p2js.exw could transpile before this feature was added. It was theGUI that already had (eg) img = c_func(x_gdk_pixbuf_new,{...}) for GTK, and img = c_func(xCreateDIBSection,{...}) for WinAPI, and needed the equivalent in JavaScript, that is once I decided a hand-crafted theGUI.js had become just a little too much effort.

In practice, of course, desktop/Phix simply quietly skips such blocks, whereas p2js simply copies the text between the two tags verbatim.

Of course it relies on "#}ilJS" not being valid JavaScript and should that occur in any comments or string literals suffers the same fate as HTML/JS always has and always will with "</script>". Incidentally, the fact that "}" is valid JavaScript is the reason for having the slightly longer terminator (whereas "}" is not valid (x86) assembly, which is why that has worked well for ilASM, albeit "stmfd r13!,{r0,r1}" is valid ARM assembly, so a "#}ilASM" terminator might yet be needed). All such blocks usually need some form of containing hll guard, for instance: 
        if platform()=JS then
-- or   elsif backend=TG_JS then -- (as found in/exclusive to theGUI.e)
            #ilJS{
                img = document.createElement("canvas");
            #}ilJS
        end if
Lastly note p2js.exw has a special pre-processing routine for theGUI.e to eliminate as much dead code as possible/practical before transpilation begins in earnest, see clip_beeq(). In time, I expect to eliminate that and make p2js smarter, skipping such code in much the same way that desktop/Phix skips "if false then" and similar platform()/machine_bits() guarded blocks.
