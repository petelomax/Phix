inflate

Definition: include builtins\inflate.e

string res = inflate(string src, integer s=1, e=-1)
Description: Inflate (uncompress) a [slice of] a binary string.

src: a binary string, from (say) [a slice of] get_text(zip).
s/e: (optional) the start/end byte positions (1-based) within the (compressed) buffer.

Should you have identified some portion of src, rather than the whole thing, s and e can help by avoiding a slice operation for which you might not have enough memory. You don't normally need to bother with them.

Returns a binary string. Errors throw exceptions.
pwa/p2js: Not supported. I have however got some fully tested code waiting in the wings, but actually these days there is a DecompressionStream("deflate-raw") which would be even better. It shd just be a matter of getting p2js to sidestep include inflate.e and slapping some replacement straight into p2js.js, or perhaps (slightly less optimal sizewise) doing it #isJS{}#isJS-style in inflate.e directly, when I get round to it, which probably means not before someone or myself actually needs it.
Comments: Should add no more than ~3.5K to the size of an executable, and much less than that via p2js, and does not require any dll/so or similar to be lugged about.

Might one day be extended to support self-extracting executables or the Phix equivalent of a resource section, that is with both in a platform-independant manner.

Written with clarity, consiseness, and correctness in mind, not speed. Should it fare badly in a pointless benchmark test I could not care less, should it need to be faster for a practical real-world use, let me know. (🤭clarity!🤣)
Example: 
-- src is a binary string from somewhere.
string res = inflate(src)
