gSlider

Definition: include theGUI.e

gdx id = gSlider([rtn value_changed=NULL, ] string attributes="", dword_seq args={})
Description: Creates a slider control, which selects a value within a limited interval. Also known as a scale or trackbar in some native systems, and pGUI called it an IupValuator or IupVal.

value_changed: (optional) a procedure identifier, see VALUE_CHANGED below.
For more information on the attributes and args parameters see gSetAttributes().
This is a paranormalised function (see technicalia).

The orientation is entirely dependent on SIZE, if none at all specified assuming horizontal.
Just as eg 100x24 is clearly a horizontal slider, it assumes x24 is a horizontally expandable horizontal slider.
Likewise 24x100 and 24x are taken to be a vertical slider. As it stands, changing that 24 only affects the tick size,
with 20/21 resulting in no ticks, and less than that starting to clip things, with 15 being OKish/boxy.

Returns: the identifier of the created element.
pwa/p2js: Supported.
Example: 
-- demo\theGUI\gSlider.exw
include theGUI.e
constant title = "Slider"

procedure value_changed(gdx slider, atom v)
    gdx dlg = gGetDialog(slider)
    gSetAttribute(dlg,"TITLE","%s:%d",{title,v*100})
end procedure

gdx slider = gSlider(value_changed),
    vbox = gVbox({slider},"MARGIN=9x9,SPACE=AROUND"),
    dlg = gDialog(vbox,title,`SIZE=240x80`)
gMainLoop(dlg)
Attributes:
VALUE A (fractional) number by default between 0.0 and 1.0 inclusive, indicating the current position. Default: 0.
Can also be set [initially] as {v,{lo,hi}} to specify the desired/permitted range of v, where {lo,hi} can be positive or negative, ascending or descending. You may however want or need to round/trunc before use.
also ACTIVE, CANFOCUS, EXPAND, FONT, MARGIN, MINSIZE, MAXSIZE, TIP, SIZE, VISIBLE.
Handlers: (optional) Specified at creation time or set using gSetHandler(slider,"VALUE_CHANGED",value_changed)
VALUE_CHANGED Called after the value was interactively changed by the user.

procedure value_changed([gdx id, ]atom v)
id: (optional) identifier of the element that activated the event.
v: the same as VALUE, which can o/c be used on-demand instead of a handler.
also KEY: All common handlers are supported. The default REDRAW handler is nothing special and can be replaced by your own version without any trouble, and example of which can be found in gVidCut.exw. Internally it uses the CLICK and MOUSEMOVE handlers, which work together as a pair, and technically could be replaced as such fairly easily enough (saving dragg and dragxy in local variables rather than in ctrl_xtra), though by that stage you may as well just use a plain gCanvas instead of a gSlider.
Technicalia As this is a paranormalised function, and with no expectation that you should attempt to memorise this lot, except maybe "ovaa", you can assume that all of the following are potentially perfectly valid, with the fairly obvious restrictions that any parameters must be in strict ovaa-order, and no args without attributes: 

                        gSlider()
                        gSlider(attributes)
                        gSlider(attributes, args)
                        gSlider(value_changed)
                        gSlider(value_changed, attributes)
                        gSlider(value_changed, attributes, args)

Note that in practice value_changed is actually defined as object, and attributes as a sequence rather than a string, but they are all manually and thoroughly verified to be of the documented types, after being repositioned via theGUI/paranormalise_vaa().

There could be all manner of little tweaks and enhancements to this control, and of course I'm happy as always to entertain suggestions, but frankly it is so dirt-simple you may as well just roll your own. See hSlider.exw, bearing in mind that is significantly complicated by stashing everything in ctrl_xtra[], to make transferring any updates back into theGUI.e simpler, whereas an application-specific control could just use file-local vars.
