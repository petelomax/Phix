UnzipBufferRaw

Definition: include builtins\LiteZip.e

integer/object res = UnzipBufferRaw(object src, dst, integer ss=1, se=-1, ds=1, de=-1)
Description: Inflate a raw compressed memory buffer into another buffer, usually larger. You must know both sizes up-front.

src/dst: memory addresses, or better yet binary strings, from (say) [a slice of] get_text(zip)/repeat(' ',de).
ss/se/ds/de: the start/end byte positions (1-based) within the (compressed/un~) buffers, optional when string(src/dst).

Should you have identified some portion of a string src, rather than the whole thing, ss and se can help by avoiding a slice operation for which you might not have enough memory, and likewise but less likely which part of dst to write to.
Note that when src is a memory address, ss must be 1 as you are expected to adjust src yourself instead, aka +ss-1, and therefore se (which cannot be omitted and because ss==1) is the length in bytes which exactly matches the 1-based indexes as would be used on strings. Ditto for dst/ds/de, of course.

Warning: There is an unfixable bug deep in the C code of UnzipBufferRaw whereby it crashes on average somewhere between every 500th and 5,000th thing you throw at it. I strongly recommend the use of inflate instead, which I've by now seen chomp through well over 50,000,000 randomly-created items without hitch.

Returns ZR_OK(=0) or a string error message. Personally I tend to declare res as integer and rely on the typecheck for debugging - failure should be reasonably rare - bad or corrupt params or unable to allocate ~54K.
pwa/p2js: Not supported - see inflate instead.
Comments: The dst parameter (or the memory it points to) is modified in-situ.
Example: 
-- [u]cs are the [un]compressed sizes
-- src is a binary string of length cs from somewhere.
string mem = repeat(' ',ucs)
integer res = UnzipBufferRaw(src,mem)
