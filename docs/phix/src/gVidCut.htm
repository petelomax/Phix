gVidCut

Somewhere between MPC-HC and LosslessCut. The following is essentially the bare minimum/briefest possible notes for use.
gVidCut can be used as a simple movie player or to edit or join video files. Currently Windows-only but Linux shd be s/fwd.
The main motivation behind this was an easy to use frame-accurate video slicer that did not treble or quadruple file sizes.
To toot my own horn, this little ditty packs quite an impressive punch in terms of functionality and overall slickness, in <2K lines.

It opens in Play mode (left) and can be cycled to Edit (right) and back by keying <E> or clicking on View/Edit mode.

The Essential Play Commands are:
<Ctrl O> or File/Open, [or drag 'n drop a movie file onto, or "open with" gVidCut*]
<Ctrl R> or File/Recent Files, [mark as Fav (which stands for favourties) to prevent removal from that list]
<Ctrl L> or File/Load Subtitles, [or drag 'n drop a .srt file onto a running gVidCut instance]
<Shift F10> or File/Properties, [show some techie stuff]
<Ctrl Q> [Quick restart, occasionally helps when audio goes awol]
Esc <Alt F4> or File/Exit,
View/Aspect Ratio, [change or permanently fix a messed-up video aspect ratio**]
<F> or <Alt Enter> or View/Fullscreen,
<Space> or triangle|bars icon or left-click on the video or Play/pause,
<Up> or click/drag volume slider or Play/Volume Up,
<Down> or click/drag volume slider or Play/Volume Down,
<M> or click speaker icon or Play/Mute,
<V> or Play/Subtitles, [hide/show 'em, when available]
<.> or square icon or Play/Stop.

Ctrl R or File/Recent opens up a simple sortable table with an auto cyclic filter. For instance if you have "abc.mp4", "bcd.mp4", and "hermit.mp4" and enter "abc" it shows that in the header and the one file match, a 'd' crops starting chars until >=1 matches, getting you the second and [bcd] in the header, a 'h' crops it all the way down to [h]. Any char with 0 matches displays the full list, and pressing backspace uncrops leading chars while >=1, aka maximising the filter-ization, iyswim. In some cases you may want to backspace-away everything, until no [] in the title, and start again. Character matches are unicode-agnostic, via the new unidecode() routine.

Spaces are treated as search term breaks, for instance "sin onno 2" matches "Sinead O'Connor - Nothing Compares 2U", and you can use terms such as "26/05" or "11:50" to match against dates and durations. Multiple search terms undergo a similar whole-term cropping mechanism to individual characters on the last term, for instance "sin onno 24" might (assuming no matches) try "onno 24" before passing just "24" to the char-cropping bit, which is skipped whenever any, even just one, whole-terms match. Overall, me very-like wot me did dare.

Loaded subtitles are indicated in the recent files list by [srt], the current/last play position by eg [4:50], or both by [srt,4:50]. The subtitles asssociation is remembered for as long as the file remains in the recent files list and gets reopened automatically. Ctrl L immediately removes any association. Likewise play resumes where it left off: press VK_HOME when needed. There is no gain/loss/difference to opening the same actual file with Ctrl O or Ctrl R.

See also/edit %HOMEDRIVE%%HOMEPATH%\gVidCut.ini on Windows (eg C:\Users\Pete\gVidCut.ini) or %HOME%/.gVidCut on Linux.
*Note (on Windows) "open with" won't work/be available unless "p -c gVidCut.exw" has been used to create a gVidCut.exe first.
**Unlike MPC-HC, changing/testing the aspect ratio is transient and does not mean "play all other files in this mangled manner too"[?!]
 - when you "fix" it modifies that specific file and automatically reverts to the default aspect ratio, as does opening any other file.

Fun fact: gVidCut implements all features of MPC-HC I care about, in less than 1% source code lines, which is also less than the number of files in MPC-HC's github repo (vs. gVidCut's one). I still rate MPC-HC highly, though, and gVidCut inevitably has way more bugs.
Note that gVidCut relies on ffprobe to properly resize/fit the player window when opening a file (display a warning when not found), and point-blank refuses to switch into edit mode when ffmpeg is not installed.

The Essential Edit Commands are:
<E> or View/Edit mode, [toggles it, disabled when ffmpeg not found]
<Ctrl+Right> or > icon or Play/Frame Fwd,   (also available
<Ctrl+Left> or < icon or Play/Frame Back,      in play mode)
<I> or [-> icon or Play/Mark In point,
<O> or <-] icon or Play/Mark Out point,
<Ctrl Z> or File/Undo,   (ie un-mark in/out, only enabled when something done/on undo stack that has not been undone)
<Ctrl Y> or File/Redo,   (ie re-mark in/out, only enabled when something undone, redo wiped when undo stack extended)
<X> or black [>] icon or Play/Extract, creates joined output.mp4, turns the icon green. Selecting an output segment turns it blue,
<Ctrl T> or a blue [>] Extract icon or File/Test plays "" or selected segment, unselecting it and making icon black/green again,
<Ctrl S> or a green [>] Extract icon or File/Save As completes your choices (S|Menu effectively black then green X).
  [In other words, clicking on the [>] icon is or can be a two-step process whereas the latter two keyboard/menu are single-step.]

Aside: mouse/seekbar interaction is strictly play-position only, there is no intent to drag in/out markers about.

Input files are shown in the left panel, completely replaced by open in play mode but extended in edit mode, and when one is selected:
<Alt+Right> or Play/Shunt/In adds the entire file to the segments list, which is shown on the right, and when one of those is selected,
<Alt+Left|Up|Down> and Play/Shunt/Out|Up|Down are enabled to remove or reorder segments, and
<Alt+End> or Play/Shunt/Clear empties the segments list (in an Undo-able fashion).
Note Ctrl Z/Y act on lone mark in/out then selected segment then end of shunted list, rather than order actually done, or any shunting.
Also note mark in/out (and undo/redo) act on the selected segment when there is one, only creating a new one when none selected.

Help/Instructions summarises these notes even further, and Help/About is the usual tat.
Attempting Edit operations when in Test/Segment Preview mode briefly advises you to press Esc in the main window title, with the exception that [warning!] in Segment Preview you can directly tweak/crop the In/Out points (applied on change of or exit segment view).

The main window title tells you when you're in Test or Segment Preview mode, the latter being entered via a blue [>] icon.
